# Pi 0.85.1 Bootstrap SDK Design

**Status:** Self-approved

## Goal

Install Pi 0.85.1 so PR monitor workers can load the Pi SDK during bootstrap.

## Problem

Pi 0.85.0 ships `dist/experimental/server.js`, which imports
`@earendil-works/pi-server`. The published Pi 0.85.0 package does not declare
that package as a dependency. A PR monitor worker therefore fails before its
bootstrap RPC can return `get_state`.

Pi 0.85.1 removes that obsolete experimental server entry point. Its CLI and
main SDK entry point load successfully in a clean side-by-side installation.
Forgejo authentication, the monitored repository, and the monitor helper are
healthy, so they are outside this change.

## Assumptions

- Pi 0.85.1 is the supported replacement for 0.85.0.
- Existing provisioning already installs the version in
  `tool_versions.runtimes.pi_coding_agent`.
- No compatibility shim is required for the defective 0.85.0 package.
- A static automated test for one declarative version value would not meet this
  repository's test-value requirements.

## Recommended Approach

Change the managed Pi version from 0.85.0 to 0.85.1. Keep the existing Renovate
annotation and provisioning path unchanged.

This is the smallest durable fix. It uses the corrected upstream package and
lets normal provisioning replace 0.85.0.

## Alternatives Considered

### Install `@earendil-works/pi-server` separately

This repairs the missing import in 0.85.0, but it creates an undeclared coupling
to an obsolete entry point. It also preserves a package version that upstream
already replaced.

### Patch the deployed Pi package

A local patch can restore service temporarily, but provisioning can overwrite
it. This repository also prohibits managed changes outside the repository.

### Disable PR monitor bootstrap

This avoids the failing import but removes monitoring behavior. It does not fix
the package defect.

## Boundaries

The change modifies only `vars/tool_versions.yml` and the required design and
plan documents. It does not change PR monitor logic, Forgejo authentication, or
repository recovery behavior.

## Verification

- Validate YAML syntax.
- Run Ansible syntax checking.
- Provision the managed Pi version on the development host.
- Confirm `pi --version` reports 0.85.1.
- Import the installed Pi SDK entry point and confirm it loads.
- Confirm the repository diff has no whitespace errors.

## Rollout and Rollback

Provisioning installs Pi 0.85.1 through mise. Roll back by restoring the 0.85.0
pin only if an unrelated 0.85.1 regression requires it; the bootstrap defect
would then return unless the missing dependency is also supplied.
