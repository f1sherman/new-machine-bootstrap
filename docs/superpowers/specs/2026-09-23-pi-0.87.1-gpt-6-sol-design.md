# Pi 0.87.1 GPT-6 Sol Upgrade Design

Status: self-approved

## Goal

Upgrade the managed Pi installation from 0.87.0 to 0.87.1 so new sessions can
use GPT-6 Sol through OpenAI Codex authentication.

## Non-goals

- Do not change Pi provider authentication.
- Do not weaken the normal 24-hour release-age policy.
- Do not change other managed tool versions.
- Do not make a paid model request during verification.

## Assumptions

- Pi 0.87.1 is the required release. Its changelog explicitly adds GPT-6 Sol
  support for OpenAI API keys and OpenAI Codex subscriptions.
- Brian's request authorizes a one-time release-age bypass for this exact Pi
  release and its exact first-party runtime packages.
- Existing live Pi sessions continue on their loaded version until restarted.

## Recommended approach

Pin `tool_versions.runtimes.pi_coding_agent` to `0.87.1`. Keep the permanent
mise and Aube age policy unchanged. During deployment only, use a narrow,
temporary trust-policy exception for the exact new `@earendil-works` package
versions required by Pi 0.87.1. Restore the source file before commit.

This follows the established Pi 0.86.1 emergency-upgrade pattern. It keeps the
normal supply-chain control active for unrelated packages.

## Alternatives considered

### Wait for the 24-hour gate

This needs no exception and is the lowest-risk option, but it does not satisfy
the requested immediate upgrade.

### Disable strict dependency aging globally

This would install the release immediately, but it would also weaken checks for
unrelated dependencies. Reject this option.

### Add GPT-6 Sol as a custom model on Pi 0.86.1

The old catalog can display the model after a catalog refresh, but Pi 0.87.1
contains the inherited provider support for OpenAI and OpenAI Codex. A custom
entry would imitate only metadata and would not provide the supported runtime
implementation. Reject this option.

## Files and boundaries

- `vars/tool_versions.yml`: authoritative Pi version pin.
- Temporary deployment exception: local worktree-only change to the rendered
  mise configuration source, restored before commit.
- `~/.config/mise/config.toml` and the mise install tree: deployed outputs made
  only by `bin/provision`.

## Verification

1. Parse the changed YAML.
2. Run focused provisioning from the feature worktree with the narrow temporary
   release-age exception.
3. Confirm `pi --version` reports `0.87.1` in a fresh process.
4. Confirm `pi --list-models` contains `openai-codex gpt-6-sol`.
5. Confirm the temporary exception is absent from the final diff.
6. Do not send a model request.

## Rollout and recovery

Provision only the current dev host. Existing sessions remain on their loaded
binary. Start a new Pi session to use 0.87.1. If provisioning fails, mise keeps
the current 0.86.1 installation available and the failure must remain visible.
