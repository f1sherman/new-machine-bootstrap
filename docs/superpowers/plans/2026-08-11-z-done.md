# `z-done` Session Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename the explicit Pi completion skill to `z-done` and shut down Pi gracefully only after synchronized completion succeeds.

**Architecture:** `managed-hooks.ts` will expose a parameter-free `done_session` tool. The tool captures the live session identity, waits for prior registry publication, invokes the existing Ruby helper once through `/usr/bin/env`, and calls `ctx.shutdown()` only for exit status 0. The skill becomes a small explicit-use instruction that calls this tool.

**Tech Stack:** Pi TypeScript extension API, Ruby completion helper, Bash/Node behavioral test harness, Ansible provisioning.

## Global Constraints

- The skill is named `z-done` and remains disabled for automatic model invocation.
- Only an explicit user request permits completion and shutdown.
- `pi-session-done` remains parameter-free and is invoked exactly once.
- Exit status `0` requests graceful Pi shutdown.
- Exit status `3`, other failures, cancellation, and timeout keep Pi open.
- The tool captures identity from `ctx.sessionManager`; it does not trust stale process-level Pi identity.
- Registry publication remains nonblocking during normal session lifecycle work.
- No shell constructs the helper invocation.
- Do not change ASR storage, adapters, or ordinary shutdown behavior.

- [ ] **Step 4: Implement the minimal `done_session` tool**

Remove `SESSION_DONE_COMMAND` and the exact Bash-command wait from `tool_call`. Register this tool near `set_session_name`:

```js
pi.registerTool({
  name: "done_session",
  label: "Complete and Quit Session",
  description: "Mark the current persistent Pi session done and quit. Use only after the user explicitly asks.",
  parameters: {
    type: "object",
    properties: {},
    additionalProperties: false,
  },
  async execute(_toolCallId, _params, signal, _onUpdate, ctx) {
    const session = registrySession(ctx);
    if (!session) {
      throw new Error("The current Pi session is not persistent.");
    }

    await registryPublicationChain;

    let result;
    try {
      result = await pi.exec("/usr/bin/env", [
        `PI_SESSION_ID=${session.sessionId}`,
        `PI_SESSION_FILE=${session.sessionFile}`,
        "pi-session-done",
      ], { timeout: COMMAND_TIMEOUT_MS, signal });
    } catch (error) {
      throw new Error(`Could not complete the current Pi session: ${String(error)}`);
    }

    const detail = (result.stdout || result.stderr || "").trim();
    if (result.killed) {
      throw new Error(detail || "Session completion was cancelled.");
    }
    if (result.code !== 0) {
      throw new Error(detail || `Session completion failed with status ${result.code}.`);
    }

    ctx.shutdown();
    return {
      content: [{ type: "text", text: detail || "Session marked done. Shutting down." }],
      details: { status: 0, sessionId: session.sessionId },
      terminate: true,
    };
  },
});
```

Do not retry. Do not call `ctx.shutdown()` on any error path.
