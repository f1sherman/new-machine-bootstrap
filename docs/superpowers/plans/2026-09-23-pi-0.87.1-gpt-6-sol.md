# Pi 0.87.1 GPT-6 Sol Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Install Pi 0.87.1 so new OpenAI Codex sessions can select GPT-6 Sol.

**Architecture:** Update the existing authoritative Pi version pin. Deploy from
the feature worktree with a temporary, exact-package Aube age exception, then
restore the exception source so the normal policy remains unchanged.

**Tech Stack:** Ansible YAML, mise, Aube, Pi CLI

**Spec:** `docs/superpowers/specs/2026-09-23-pi-0.87.1-gpt-6-sol-design.md`

## Global Constraints

- Pin Pi to exactly `0.87.1`.
- Keep the permanent 24-hour release-age policy unchanged.
- Scope the temporary bypass to exact Pi 0.87.1 first-party package versions.
- Do not change other managed tool versions.
- Do not send a paid model request.
- Do not retain a static version-string test.

### Task 1: Update the managed Pi pin

**Files:**
- Modify: `vars/tool_versions.yml`

**Interfaces:**
- Consumes: `tool_versions.runtimes.pi_coding_agent` in the existing mise
  template and common-role install tasks.
- Produces: a rendered mise tool request for
  `npm:@earendil-works/pi-coding-agent@0.87.1`.

- [ ] **Step 1: Record the current pin**

Run:

```bash
yq '.tool_versions.runtimes.pi_coding_agent' vars/tool_versions.yml
```

Expected: `0.87.0`.

- [ ] **Step 2: Update the pin**

Change:

```yaml
pi_coding_agent: 0.87.0
```

to:

```yaml
pi_coding_agent: 0.87.1
```

- [ ] **Step 3: Validate YAML and the focused value**

Run:

```bash
yq '.' vars/tool_versions.yml >/dev/null
yq '.tool_versions.runtimes.pi_coding_agent' vars/tool_versions.yml
```

Expected: both commands succeed and the second prints `0.87.1`.

- [ ] **Step 4: Commit the pin and plan**

Run the repository commit workflow with:

```text
chore(pi): upgrade to 0.87.1 for GPT-6 Sol
```

Include `vars/tool_versions.yml` and this plan.

### Task 2: Deploy with a bounded age exception

**Files:**
- Temporarily modify and restore:
  `roles/common/templates/dotfiles/mise/config.toml`
- Deploy output: `~/.config/mise/config.toml` and the mise Pi install tree

**Interfaces:**
- Consumes: the 0.87.1 pin and existing focused provisioning path.
- Produces: a fresh `pi` executable at version 0.87.1 without a permanent policy
  exception in Git.

- [ ] **Step 1: Save the source template checksum**

Run:

```bash
sha256sum roles/common/templates/dotfiles/mise/config.toml
```

Record the checksum.

- [ ] **Step 2: Add an exact temporary trust-policy exception**

Extend only the Pi tool's `trust_policy_excludes` list with the exact 0.87.1
`@earendil-works` packages reported by the failed closed install. Start with the
known runtime set: `pi-coding-agent`, `pi-ai`, `pi-tui`, `pi-agent-core`,
`pi-server`, `pi-client`, `pi-protocol`, `pi-telemetry`, and `chord`. If Aube
reports another young package, inspect it and add only its exact package and
version before one bounded retry.

- [ ] **Step 3: Run provisioning from this worktree**

Run:

```bash
bin/provision
```

Expected: provisioning succeeds with zero failed tasks and installs Pi 0.87.1.

- [ ] **Step 4: Restore the source template**

Restore `roles/common/templates/dotfiles/mise/config.toml` to its committed
content. Confirm its checksum matches Step 1.

- [ ] **Step 5: Verify the deployed executable and catalog**

Run:

```bash
pi --version
pi --list-models | grep -E '^openai-codex +gpt-6-sol '
```

Expected: `0.87.1` and one GPT-6 Sol model row.

- [ ] **Step 6: Verify the final diff and working tree**

Run:

```bash
git diff --check
git status --short
git diff origin/main...HEAD -- roles/common/templates/dotfiles/mise/config.toml
```

Expected: no whitespace errors, no temporary template diff, and only task files
remain in the branch history.
