* Source workspace setup: reuse an existing isolated workspace. When a new branch or worktree is needed, run `repo-start <branch>` and use its returned path. This is the shared entry point, including when a generic skill shows direct Git commands. Keep the repository's worktree preference. If setup fails, inspect `repo-start --help` and the reported error; preserve the current checkout instead of bypassing the guard.
* Source workspace cleanup: use `repo-end` after integration. Use `repo-end --closed` only for a fully published branch with a closed, unmerged PR. Check `repo-end --help` and the relevant state before declaring cleanup blocked. Unpublished work with changes absent from main has no supported discard mode: preserve it and report that limitation. Do not publish abandoned work just to enable cleanup. For an environment-owned worktree, use its owner's retirement process instead.
